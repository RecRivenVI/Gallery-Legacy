# 实时分批更新

实例配置 `liveUpdates: true` 启用。旧配置默认关闭，仍使用静态 READY 读取；更改模式后先重启服务再扫描。正式生产实例不会因为更新源码自动开启。

静态模式现已支持新 READY 发布后的安全自动接入，不再要求每次扫描后手动重启。live 模式额外提供扫描期间完整批次可见。首次空库启动提供空视图及扫描状态，首次完整扫描发布前不展示 BUILDING 内容。

## 数据边界

- READY generation 继续是不可变检查点，不能原地修改。
- 首次从已验证检查点初始化 `instanceRoot/live/catalog.sqlite`。此文件包含原 Catalog 事实表、独立命名的 live Search 表、修订号与 ID 高水位。它不是 BUILDING 扫描候选。
- 完整作品批次在同一个 SQLite 事务中更新 Catalog、Search、计数和 revision，提交后才对读者可见。读取列表、详情与响应版本使用同一读事务。
- 不完整作品不提前展示；metadata 异常仍可保留完整物理作品。作者全局资料在确认完整前保留已有权威，不按扫描到达顺序覆盖。
- 取消/失败不撤回已提交批次。下一次更新从实时事实继续。删除只在最终完整范围确认并完成检查点时应用。
- 扫描完成另存并发布完整 Catalog/Search 检查点。实时读者继续使用同一 live epoch，不必为正常分批新增重启。
- 手工发布/回滚另一个检查点后仍需重启选择它；不能在另一个 Runtime 正在读取时替换 live 文件。

## 身份与分页

`generationId` 在实时读取模式中是稳定 live epoch；`revision` 是该 epoch 内的可见提交序号。Manager 同时显示已发布检查点与实时修订，二者不要混用。

作品列表支持 `rev`。cursor 绑定查询、排序、epoch 和 revision。提交后旧页继续请求时返回 `409 CONTENT_CHANGED`，而不是悄悄拼接新旧页造成漏项/重复。状态轮询不会改写当前列表的分页版本。

媒体 ID 使用持久高水位，不复用删除后的 ID；未变化路径的媒体保留 ID。实时媒体 URL 还绑定物理身份 `k`，不能把旧 ID 指向另一个文件。此 key 是身份摘要，不是媒体内容 hash。不相关作品提交不会使正在看的媒体 URL 失效。

## 前端体验

作品流第一页、停在顶部、未输入且阅览器关闭时，可节流自动更新。向下浏览、翻页、搜索或打开阅览器时只显示“有新内容”；必须主动点击更新，关闭阅览器不会擅自刷新。当前版本不自动把新卡片插入用户正在看的中间位置。

状态包含各平台最近修订号：其他平台提交不会触发当前平台列表重载。自动重载间隔至少 5 秒。分页仍绑定全局版本；旧游标被拒绝时会提示主动刷新，不混合两个版本。

## 状态性能

实时库的总数、平台计数与 metadata 状态计数在作品提交事务中同步维护。状态请求只读取小型聚合表，不再每批扫描整库。旧实时库在停服后的准备阶段一次性升级统计表，保留已有作品、epoch 和修订号；这不改变 Catalog Schema v4 或 READY 文件。

进程存活状态在后台异步核验并合并重复请求，不在 HTTP 主线程等待 PowerShell。停止、接管等管理操作仍校验真实进程身份，失败的存活查询不能作为杀进程的依据。

## 恢复与限制

首次初始化实时 Search 可能较慢，这是从数据库构建读模型，不是扫描真实媒体。扫描在慢校验之前写 PREPARING 并取得任务锁，不把这段等待误报为启动失败。

live 数据损坏不会自动丢弃重建。先停服，可在数据版本页明确确认“重置实时库”；原实时库移到实例 temp 备份，再从已发布检查点初始化。未成检查点的批次将不再展示，因此必须用户确认。源文件、READY 数据和生产其他实例不受影响。

live 模式下变更物理根需要先关闭实时模式、建立新根的完整检查点，再重新启用；不把新根记录交给旧根 Runtime 服务。

mtime/size 权威的原有限制继续存在；不读取/计算媒体内容 hash。WAL/SHM 仅属于可写 live 区域，不能进入 READY generation。没有实施 Go、增量文件 watcher 或多租户。
