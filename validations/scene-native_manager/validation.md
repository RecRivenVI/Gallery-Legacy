# 原生管理与服务生命周期

## 目标

在新合成实例上验证四页管理、持续轮询和生命周期，保留 PID／创建时刻／可执行身份及实例认证；不使用真实图库、生产或历史宿主。

## 运行

1. 按开发工作流准备合成库和仓库外候选构建，只运行本轮新建实例。
2. 运行完整 npm test，确认原生生命周期与原生管理操作两组实际执行；Go test、vet、race 与合成集成使用同一冻结候选。
3. 在原生窗口依次操作更新、访问范围与封禁开关、设置保存并重启、排查，再重复切换四页并观察轮询；目录选择和托盘实际点击交用户补充。
4. 关闭窗口到托盘后再打开；退出管理器后确认独立服务仍可用，重新连接、重启、停止与启动仅针对本测试实例。
5. 用新实例读取失败及受控接口错误验证服务状态、访问／日志错误与恢复；不延长超时、添加重试或降低身份核验。
6. 截默认与最小窗口、深浅主题、更新中、错误和环境检查；网页另截电脑／平板／手机的加载、空、错误。同时记录实际外框、内容尺寸及 DPR，截图与结果放到仓库外，逐张查看后写 INDEX。

## 通过标准

- 相同管理文档的四个 hash 页面可以持续调用；不同文件／来源／查询串／子 frame 不得取得原生控制。
- 四页主要操作与周期读取无控制错误；PID 复用、令牌不符、身份无法读取继续被拒绝。
- 原生管理器真正退出与独立 Runtime 的生命期分开核对，不以测试启动壳的等待误判服务卡死；失败收尾不留下本测试的在用控制连接。
- 失败只在对应面板显示操作、原因与下一步；服务读取失败不保留运行中显示，空／错误互斥，检查中与已结束结果可区分。
- 真实托盘点击、文件对话框、输入法、真机与主观观感分别记录用户验收，不把自动测试替代人工验收。
