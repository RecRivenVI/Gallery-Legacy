# 后端替换差分

## 目标

对照冻结 Node 实现，确认 Go 的公共读取、本机身份与恢复保持一致，且没有第二个写入者。全部使用合成素材；不连接生产或真实配置，不控制历史 Runtime。

## 运行

1. 指定 GALLERY_TEST_ROOT 为本轮仓库外新合成根，GALLERY_NODE_REFERENCE_ROOT 为保留的 Node 冻结构建根；前者只存新输入与结果，不能指向旧实例。
2. 通过 npm run test:protocol 生成 Node 查询黄金结果并运行 Go 差分；保留原始失败与修正后的结果。
3. 运行 test:schema、test:reader、test:recovery；Reader 需 GALLERY_SCANNER，四个差分脚本附加 `-- --race` 可实际测试黄金用例。恢复包括 READY／指针、事实异常、从快照新建与旧 live v1／v2 升级，不读取源内容来代替存储校验。
4. 对本批 HTTP／媒体／控制追加同场景的两侧结果，比较 DTO／状态／正文／必要头与最终 SQLite 聚合，时间、临时端口和随机实例身份仅按合同排除，不归一化业务值。
5. 覆盖坏 URL／Unicode、空／坏库、丢失／变化／链接文件、边界 ID／Range、过时修订、错误身份、并发启动、取消／崩溃与恢复；失败最多原样重试一次，再查原因。
6. 候选冻结后运行完整 Go、vet、race、合成集成和既有原生四页／网页测试；主题先设置，截图后实际查看，再写 INDEX。证据放仓库外，不进入源码。

## 通过标准

- 每批仅在已完成的差分范围结论为“一致”后切换与提交；未验证写“无法比较”，不以测试数量代替证据。
- 两侧稳定 DTO、身份、顺序、失败码、媒体字节和必要响应头一致；坏库／身份／来源场景不产生授权扩大或已提交数据丢失。
- 服务与管理器端到端主要操作完成；日志与页面错误可恢复。真实托盘、输入法和日常手感保留用户验收，自动结果不冒充。
