# 技术栈迁入边界核对

调查日期 2026-10-21。

## 问题

已经打磨的 Go 扫描器和 CanvasKit／四页管理端能否独立替代全部 Node 产品代码？

## 方法

核对当前工作树的调用、原始 Go acceptance 测试、Node Reader／媒体依赖及合成数据差分。没有读取真实图库或配置，没有对在用服务操作。

## 发现

- Go 可以标准库遍历九平台、解析 metadata、保留物理事实、执行完整作品事务和增量签名复用；Node 差分基准仍用于校对字段、作者权威与媒体事实。
- 候选浏览界面的 API 适配依赖 Node HTTP、CatalogReader、QueryIndex 和媒体服务；扫描语言变化不替代这些模块。
- schema 初始化、READY 检查点和显式恢复、实例所有权、本机管理及 Electron 生命周期仍依赖 Node。直接删除 Node 会同时破坏读取与恢复，不只是减少重复扫描代码。
- 原生宿主与身份验证存在整理前的失败／长等待；合成页面可打开、单次管理操作成功，不足以证明全部轮询和原生生命周期可用。

## 结论

以[迁入决策](../design/adr-2-stack_promotion.md)为准：正式 live 扫描启动唯一 Go writer；保留尚需的 Node 读取／媒体／恢复和控制。退役已完全替代的旧 DOM 入口，不在整理时另写 Go HTTP 或降低路径／身份／事务要求。替代工作的剩余范围列在[技术债](../project/debt-runtime.md)，不能称整个后端已经 Go 化。
