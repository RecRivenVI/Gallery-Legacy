# 清单、准备与写入

全量和增量优先取本机 Everything HTTP 清单。清单只提供候选事实，作品的首次准备仍须原生枚举，保存逐文件属性清单与作者资料投影；增量逐项匹配已提交文件清单后跳过全部作品 I/O。不检测大小和修改时间都不变的内容替换。

## 清单合格性

HTTP 与 IPC 必须属于监听 54321 的同一进程，数据库已加载且不忙。HTTP 流必须完整、行数一致、路径在根内、无重复且父目录闭合；根和作者成员与原生枚举交叉核对。不合格时丢弃该平台清单并报告需要确认；只有用户同意才回退原生遍历。

新作品和变化作品的完整事实来自原生枚举；被索引排除的后代不能匹配其此前的完整文件清单。因此不把 HTTP 返回的 totalResults 当作文件系统完整证明。删除仍需完整范围和原生不存在确认。

## HDD 读取顺序

全量和增量对寻道敏感的本地盘启动短生命周期的提权辅助进程。它用 NTFS USN/MFT 控制接口提取范围内 metadata.json 的位置；不保存范围外条目，不读取媒体流，不改变 HTTP 服务或管理器的权限。只缓存根和作者目录，不缓存每件作品的父目录。

非驻留元数据按首个数据 extent 排序；驻留元数据按所属 MFT 记录的物理位置排序，使用 MFT 自身 extent 映射，不能假定 MFT 连续。缺少位置或接口不可用时按目录顺序处理，并记录实际覆盖量。位置仅用于调度，不授权读取路径、复用或删除。FSCTL 返回的逻辑记录不再套用裸盘更新序列数组修复。

排序后的单平台生产者依次预读元数据，复用原生准备中的大小、修改时间与只读句柄核验。全局和物理盘准入约束依旧有效；解析可并行。辅助进程结束即关闭；取消只操作本次启动返回的进程句柄。

## 准备与提交

准备好的作品进入共享字节预算队列。唯一 writer 按平台聚合短批次，数量、字节或时间窗口触发提交，Catalog、Search、计数、revision 和文件清单同事务。HDD 每块物理设备仅一个源读取者，按作者作品数排序的发布使用实例磁盘暂存，与物理读取顺序解耦。SSD 作者准备并发按其作品和文件数自适应。作者定稿独立于准备 worker，不占住准备 worker 等待磁盘；所有作品处理完成后才提交作者资料。平台完整核对后才能删除。

大作品超过内存观察缓冲时进入实例私有 SQLite 暂存，目录深度和媒体数量不作丢弃依据。媒体、文件清单与正文逐行交给同一个作品事务；没有完成标记的暂存不能发布。中断后保留已提交作品，持有扫描租约的下一次任务回收暂存并重新准备该作品。元数据单文件上限保持原配置，不提高队列内存预算。

实例日志包含位置收集耗时、准备/目录枚举/核验/解析/映射/数据库写入/提交耗时，以及元数据内容读取次数和平均耗时。并行累计计时不能直接相加视为墙钟总耗时。

接口依据：[Everything HTTP](https://www.voidtools.com/support/everything/http/)、[Everything IPC](https://github.com/voidtools/ES/blob/main/src/everything_ipc.h)、[NTFS 文件记录](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_ntfs_file_record)、[NTFS 属性头](https://learn.microsoft.com/en-us/windows/win32/devnotes/attribute-record-header)。
