# 管理器绑定画廊与扫描生命周期

## 状态

已接受。

## 背景

用户在 2026-10-22 的 101 号决定纠正 99 号中的独立存活要求：画廊与扫描都与管理器绑定，只能在管理器内启动。现有窗口关闭隐藏与真正退出的区别保留。冻结 Node 的独立存活行为不再是该项标准，其他协议与数据语义不变。

## 决策

Electron 保留窗口、托盘和固定白名单；Go 作为管理器拥有的子进程，通过继承的输入通道接收管理命令。原生核验直接父进程与完整身份，通道关闭或管理器身份消失即正常收尾；不以 PID 单独判断归属。产品外部启动命令不再创建服务或扫描。

Go 管理器会话拥有 HTTP 服务与扫描任务。真正退出先取消并等待扫描结束，保留完整作品批次已提交的事务，再关闭服务、数据库和本实例所有权。没有硬杀或停止其他实例的回退。窗口隐藏仍保留同一会话；重新打开管理器从持久实例状态恢复。

## 后果

正常退出可能等待正在提交的事务结束，不提前报告退出完成。静态检查点只发布完整 READY；取消或失败不覆盖已发布检查点。测试须覆盖进行中退出、结束后退出、隐藏／重开、外部启动拒绝与事务保留。历史生产宿主不在本轮改变。
