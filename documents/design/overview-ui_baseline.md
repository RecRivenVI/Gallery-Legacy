## 0. 这份文档的地位与协作方式

### 0.1 文档的地位

1. 本文是画廊系统网页端和管理端的**设计基线**，2026-10-03 冻结，之后不再修改。
2. **冻结之后的设计决定，记在与本文同一目录的《设计变更记录.md》里**（还没有这个文件时就新建）。每条决定写一段：
   - 日期；
   - 来源：用户的哪条问题报告或需求；
   - 改了什么，并注明对应本文的哪一节；
   - 截图或录屏放在哪里。
3. **《设计变更记录.md》与本文冲突时，以变更记录里日期最新的那一条为准。**
4. **附录 B 是用户的原话**，本文是对这些原话的整理和细化。如果你发现本文和原话的意思不一致，以原话为准，并把差异写进设计变更记录；拿不准时问用户。
5. 用户手里有一份设计画布（方向 B「展墙」）可以作为视觉参考。看不到画布时，以本文为准。
6. 文中的尺寸单位都是逻辑像素（CSS px / dp），不是物理像素。

### 0.2 角色

- **用户**：画廊的拥有者和日常使用者，也是需求的唯一来源。用户和你沟通的方式，就像在 GitHub 上提 issue 的普通用户一样：报告问题、提出需求、试用新版本后给反馈。
  - 用户不是技术人员，不审代码，也不读测试报告，只看实际效果。
- **你（开发者 / 维护者）**：负责设计细节、实现、测试、发布和回退。
  - 用户的每一条消息，你都当作一个 issue 来处理。
  - 本文和《设计变更记录.md》是你做设计决定的依据。
  - 以前由设计评审人做的检查（第 2.5 节的自查清单），现在由你在每次发布前自己完成。

### 0.3 怎么处理用户的消息

**问题报告（bug）**

1. 先在沙盒里复现。描述不够你复现时，只问缺少的那一项，一次问完，例如“是在电脑上还是手机上？能截一张图吗？”
2. 修好后回复用户：
   - 一句话说明原因；
   - 修好后的截图或录屏；
   - 在哪个版本里能用到。
3. 顺手检查其他页面有没有同类问题，一起修好，并在回复里列出来。

**需求**

1. 先判断属于哪一种：
   - **本文已经写了**，只是还没做或者做错了：按本文做，当作问题报告处理。
   - **本文没写**，但能按第 2 章的方法直接定下来的细节：你自己定。做完后给用户看截图或录屏，写进设计变更记录。
   - **会改变本文已经定下的设计**，或者有几种明显不同的做法：先给用户看两三个方案的示意（截图、录屏或简单的样张），写清楚各自的差别，等用户选定再做。
2. 需求和本文的规则冲突时（例如需要一个本文没有允许的确认框），说明冲突在哪里，请用户决定。
3. 用户用文字描述视觉效果时，先做出来给用户看，再一起调整。不要只回复“已实现”。

**怎么回复用户**

- 用中文，句子短，先说结论。
- 不出现代码、命令行和内部术语。需要用户操作时，写清楚在哪里点、看什么，不超过 3 步。
- 只问必须由用户回答的问题，能自己决定的不要问。
- 不要把没有得到用户确认的事情写成“用户已确认”。

**发布**

- 每次发布前按第 2.5 节自查，按第 8.4 节写发布说明。
- 替换用户正在使用的版本之前，必须得到用户同意；同时保留一份可以退回的旧版本，并告诉用户怎么退回。

### 0.4 阅读顺序

1. 先读第 0、1、2 章：协作方式、工作规则、设计方法。以前的前端问题，大部分都出在这几件事上。
2. 第 3～5 章是**设计系统**：颜色、尺寸、控件、动效。所有页面都只能用这里定义的东西拼出来。
3. 第 6、7 章分别是网页端和管理端的**具体页面**。
4. 第 8 章是技术、性能、冻结时的进度和发布要求。
5. 第 9 章是已经按默认做法实施、等用户试用后确认的事项。
6. 第 10 章是本文冻结前的修订记录，只作历史参考。
7. 附录 A 是现有产品的约束，附录 B 是用户的原话。

## 1. 工作规则（必须遵守）

### 1.1 界面文案

1. 只写用户需要知道的内容。一句能说清的，不写两句。
2. 界面上**不出现**以下内容：
   - 安全声明、“只读保护”、实现原理；
   - 内部术语：generation、Catalog、Search、READY、checkpoint、live、retention、RSS、Heap、metadata 等；
   - 英文和中文混杂的说明句。
3. 错误提示只写两件事：**发生了什么 + 用户可以怎么做**。例如：“缩略图生成失败：文件已损坏。可以在‘排查’里查看是哪个文件。”
4. 同一个概念只用一个名字，名字以第 2.3 节的术语表为准。
5. 本文没写到的文案，用最短的说法，并在发布说明里列出来。

### 1.2 防御代码与保护措施

这个项目之前有很多“防御性”代码和界面：层层确认、反复声明、没人用的回滚入口、到处兜底的 try/catch。它们让产品变得繁琐，还藏住了真正的错误。从现在起：

1. **只在边界做校验。** 边界指用户输入、文件系统、网络、外部程序。内部函数之间互相信任，不重复检查同一件事。
2. **真正的不变量只实现一次，放在最底层。** 例如“绝不写入源文件”，由写入层的一个守卫保证。不要在每一层都再检查一遍，更不要在界面上反复声明。
3. **不吞错误。** 不写空的 catch，也不写“出错就返回默认值”的兜底。错误要带着原因传到能处理它的地方，最终用第 1.1 节的格式告诉用户。
4. **不写“以防万一”的东西。** 包括：设计说明以外的确认框、勾选确认、重复提示、隐藏入口、备用功能、没人要求的配置项、功能开关、兼容层。
   - 例外：本文明确要求保留的兼容，例如 Venera 的源和已收藏的链接。
5. **需要确认的操作只有第 7.7 节列出的几项**，其余操作直接执行。
6. **如果你认为某处确实需要额外保护**，先在回复里提出来：写明理由、不加会出现的具体后果、你的方案。等用户同意后再做。
7. **被本文去掉的功能，删掉它的界面代码。** 不要保留隐藏入口。后端机制是否保留，由你按技术判断决定（第 7.5 节）。
8. **不可能发生的状态不要写分支处理**，用类型或断言表达。例如界面上出现过的 `NaN`，说明数据源的类型没管好，不应该在显示层补一个“如果是 NaN 就显示 —”。

### 1.3 回复与发布

1. 回复和发布说明只写三样东西：**结论、证据（截图和录屏的位置）、需要用户决定的问题**。不写过程叙述，同一件事不重复说明。
2. 发布说明的要求见第 8.4 节。
3. **测试和截图只能在 `design-review/` 的合成沙盒里做**，使用合成数据，不得接触真实资产库和真实配置。这套沙盒和生成脚本已经存在，继续使用。
4. 复现用户报告的问题时，也先在沙盒里复现。确实需要用户的真实情况时，请用户提供截图或描述，不要自己去读真实数据。

### 1.4 遇到不确定的事

- **本文没写、又会影响用户看到的东西**：能按第 2 章的方法定下来的，你自己定，发布时给用户看，并写进设计变更记录；有几种明显不同的做法时，先给用户看两三个方案再定。
- **本文写了、但你认为不合理**：先照做，同时在回复里提出你的意见和方案，用户同意后再改。
- **纯技术实现细节**：你自己决定，不必告诉用户。

### 1.5 不能动的东西

1. **只读**：画廊不修改、不重命名、不删除用户的源作品和 metadata（附录 A）。
2. **兼容**：以下几项必须继续可用：
   - Venera 源和已收藏的 ID；
   - 稳定的 `/p`、`/f` 分享路径和短链；
   - 生产域名和 localhost 访问；
   - 托盘后台和正式 exe 入口。
3. **生产版本**：用户正在使用的版本，只有在用户同意后才能替换；替换时保留一份可以退回的旧版本。
4. **改动范围**：只改和这次请求有关的东西。不要顺手重构、整理目录或改动无关的代码。确实觉得有必要时，先在回复里提出来。

## 2. 设计方法（给实现者的 UI/UX 要点）

这一章是为了让你以后自己补设计时，结果和现有设计一致。

### 2.1 从任务出发

1. 先问“用户最常做什么”。最常做的事放在最显眼、最少步骤的位置，不常做的事往后收。
   - 例：管理端最常用的是“更新图库”，所以它是首页的主体；数据版本回滚从来没用过，所以直接从界面上去掉。
2. 一个区域最多一个主要按钮（实心强调色）。其余都是次要按钮。
3. 能直接做的就直接做。确认框只留给**慢、不可逆、或影响别人**的操作。

### 2.2 一致性

1. **只用设计系统里的零件**（第 3、4 章）。颜色、尺寸、圆角、间距一律引用变量，不写死数值。
2. 同一种控件只有一种样子。现有前端最大的问题就是同一种按钮有好几种样式、确认方式有四五种，这次不能再出现。
3. 每个控件都要有完整的状态：默认、悬停、按下、选中、禁用、键盘焦点。每个页面都要有完整的状态：加载中、空、出错、部分成功。
4. 新做一个东西之前，先找找有没有现成的同类零件。有就用，没有就先在本文第 4 章里定义，再使用。

### 2.3 术语表

| 概念 | 统一叫法 | 不要用 |
|---|---|---|
| 一个作品目录 | 作品 | 图集、帖子、条目 |
| 作品里的一张图或一段视频 | 页（第 3 页） | 媒体、图片项 |
| 看大图的界面 | 看大图 | 灯箱、Viewer、查看器 |
| 看大图右侧的信息栏 | 详情栏 | 信息面板、侧栏 |
| 左侧的平台列表 | 侧边栏 | 导航栏 |
| 九个平台 | 平台 | 来源、站点 |
| 直接浏览磁盘目录的入口 | 全部文件 | 文件浏览、文件根 |
| 邮件式左右布局 | 分栏 | 分屏、预览模式 |
| 扫描并入库 | 更新图库 | 扫描、增量、发布 |
| 重新扫描全部内容 | 全部重新扫描 | 全量重提取 |
| 管理端的问题排查页 | 排查 | 诊断、验证 |

### 2.4 布局规则

1. **间距**只用这些值：2、3、4、8、12、16、20、24。
2. **一组方形按钮：按钮之间的间距 = 按钮到外框的距离。** 例：分段控件内边距 3，按钮间距也是 3；看大图的顶栏上下留白 8，按钮之间也是 8。
3. **同心圆角：外圆角 = 内圆角 + 两者之间的间距。** 圆角矩形套圆角矩形时，内外圆角共用一个圆心，四周的间距才会均匀。间距明显大于圆角时（比如面板里离边缘 16 的按钮）不需要同心。
4. 对齐：同一列的元素左边缘对齐；图标都放在同一条竖线上（侧边栏收起时图标不能移动，就是靠这条规则）。
5. 文字过长时**不用省略号**，用淡出（第 4.9 节）。

### 2.5 发布前的自查清单

每次发布前逐条检查，并在发布说明里写明“已自查”：

- [ ] 所有颜色、尺寸、圆角、间距都来自变量，没有写死的数值
- [ ] 所有控件的悬停、按下、选中、禁用、焦点状态都与第 4.1 节一致
- [ ] 圆角嵌套的地方都同心；成组的方形按钮间距等于边距
- [ ] 没有省略号；所有溢出都是淡出，淡出的出现和消失都有过渡
- [ ] 没有任何瞬间切换：位置、大小、透明度的变化都有动画（第 5 章）
- [ ] 所有动画都能中途打断，并且从当前位置平滑转向
- [ ] 没有出现内部术语和多余说明；文案符合术语表
- [ ] 没有新增本文以外的确认框、提示和入口
- [ ] 深色和浅色、电脑和手机都截图检查过
- [ ] 加载、空、出错状态都截图检查过
- [ ] 每张截图写说明前先看过图，说明和图一致（以前出过的错：写着“加载中”的图其实已加载完；写着“转为看大图”的图其实还是分栏；访问页截成了空白）
- [ ] 层级正确：弹出面板、抽屉、看大图里的面板都在最上层；只属于某一页的东西（例如设置页的保存条）不出现在别的页；任何文字之间没有重叠
- [ ] 同一种控件同一种样子，网页端和管理端也一样（以前出过的错：“设为背景”只有文字没有按钮底；管理端开关和网页端不同）
- [ ] 用户看到的文字里没有程序数据：JSON、undefined、NaN、服务器内部路径
- [ ] 文字对比度按实际底色算过，至少 4.5 : 1（第 3.1 节）
- [ ] 英文按单词断行，中文可以任意断行
- [ ] 有性能相关改动时，在同一台机器上测过改动前后，退步要写进发布说明

## 3. 设计系统：基础

### 3.1 颜色

两套主题：跟随系统 / 深色 / 浅色。

| 变量 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| bg | `#111213` | `#F2F2F0` | 页面底色（默认纯色背景） |
| glass | `rgba(24,24,26,.80)` | `rgba(250,250,248,.84)` | 悬浮层：侧边栏、顶栏、页码条、底栏、详情栏、弹出面板 |
| edge | `rgba(255,255,255,.075)` | `rgba(0,0,0,.08)` | 1px 描边、栏与栏之间的分界 |
| div | `rgba(255,255,255,.09)` | `rgba(0,0,0,.09)` | 分割线 |
| fg | `#EDEDED` | `#161616` | 主要文字 |
| fg2 | `#CFCFCF` | `#333333` | 正文、标签文字 |
| muted | `#A3A3A3` | `#555555` | 次要文字 |
| faint | `#8A8A8A` | `#6B6B6B` | 数量、分组标题 |
| accent / accent-ink | `#FFFFFF` / `#111111` | `#111111` / `#FFFFFF` | 主要按钮的底色 / 文字 |
| tint | `rgba(255,255,255,.07)` | `rgba(0,0,0,.05)` | 悬停叠加层 |
| tint-press | `rgba(255,255,255,.12)` | `rgba(0,0,0,.09)` | 按下叠加层 |
| on | `rgba(255,255,255,.13)` | `rgba(0,0,0,.08)` | 选中底色 |
| field | `#1C1C1E` | `#FFFFFF` | 输入框、分段控件底 |
| tag-bg | `rgba(255,255,255,.10)` | `rgba(0,0,0,.065)` | 标签、次要按钮底 |
| chip | `rgba(0,0,0,.60)` + 模糊 | 同左 | 作品图片上的标签 |
| stage | `#0C0C0D` | `#0C0C0D` | 看图区域（**浅色主题下也是深色**） |
| ok / warn / err / info | `#3CCF7E` / `#E8B04B` / `#FF7A70` / `#7AB8FF` | `#1B7A43` / `#8F6200` / `#C4362C` / `#1F66C2`（原来的亮色在浅色底上只有约 2:1，改深后约 4.8～5.6 : 1） | 状态色，只用于状态图标和少量状态文字 |

**对比度规则**：所有文字与它实际所在的底色（包括毛玻璃叠在默认背景上的结果）至少 4.5 : 1。上表的值已按这条规则核对过；以后改颜色时先算对比度，不达标的不要用。

强调色就是黑白本身（方向 B 的设计意图：界面退后，作品就是颜色）。不要再引入金色或其他品牌色。

### 3.2 字体

- **界面字体**：思源黑体 / Noto Sans SC（自绘时需要随程序附带，建议按常用字分包加载）。系统字体版可以回退到苹方 / 微软雅黑。
- **表情符号**：标题和作者名里常有表情符号，必须能显示。随程序附带 Noto Color Emoji，只在可见文字里出现表情时才加载。其他文字（阿拉伯文、希伯来文等）暂不处理，等用户遇到时再说。
- **展示字体**：Outfit，只用于页面路径等处的拉丁字母（Outfit 没有中文字形）。品牌字“画廊”用 Noto Sans SC，字重 600。
- **等宽字体**：JetBrains Mono，只用于管理端的地址、路径和日志。
- **数字**：一律等宽数字（tabular），避免跳动。

| 用途 | 字号 | 字重 |
|---|---|---|
| 数量、分组标题、角标 | 11 | 400 / 700 |
| 次要文字、说明 | 12 | 400 |
| 正文、控件文字 | 13 | 400 / 500 |
| 面板标题 | 14 | 600 |
| 页面路径 | 15 | 600 |
| 品牌字、详情标题 | 16 | 600 / 700 |

### 3.3 圆角

| 变量 | 值 | 用途 |
|---|---|---|
| r-xs | 2 | 作品图片上的标签和角标（卡片 6 − 内缩 4） |
| r-ico | 3 | 侧边栏平台图标 |
| r-sm | 4 | 组内的按钮、缩略图、标签 |
| r-card | 6 | 作品卡片 |
| r-md | 7 | 34 高的独立控件和控件组（4 + 3） |
| r-nav | 10 | 侧边栏项的高光（3 + 7） |
| r-pop | 12 | 弹出面板、管理端面板（菜单项 4 + 内边距 8） |

**G2 连续曲率**：所有圆角都使用连续曲率（squircle），而不是圆弧。
- 自绘时，按“尺寸 + 圆角”预先生成轮廓并缓存。
- 视觉大小要与上表的圆弧圆角一致，连续曲率的控制长度约为圆弧半径的 1.5 倍。
- 同心规则对连续曲率同样适用：外轮廓取内轮廓向外偏移间距后的形状，不要简单地按比例放大。

### 3.4 尺寸

| 侧边栏宽 | 展开 240，收起 50 |
| 顶栏 | 第一行 50，第二行 42（含底部 8 的留白） |

| 控件组 | 高 34，内边距 3，组内按钮 28，按钮间距 3 |

| 底栏缩略图 | 48 × 48，间距 8 |
| 作品网格 | 列间距 8，行间距 16 |

### 3.5 毛玻璃

用在悬浮于背景之上的元素：侧边栏、顶栏、页码条、看大图的顶栏 / 底栏 / 详情栏、看大图里浮在图片上的所有按钮（左右翻页按钮等）、弹出面板、作品图片上的标签。

- 参数：模糊半径 24，饱和度 1.3，叠加第 3.1 节的 glass 色。
- **使用作品图片做背景时**：glass 的不透明度改为 0.90（深色 `rgba(24,24,26,.90)`，浅色 `rgba(250,250,248,.90)`），配合第 6.9 节“背景淡化”的下限，保证浮层上的文字在最亮 / 最暗的背景图上也达到 4.5 : 1。纯色背景时不变。
- **性能要求**：实时模糊只用在固定的大面积元素上（侧边栏、顶栏等，数量固定）。
  - 作品图片上的标签数量很多，不要每个都实时模糊。做法是每张缩略图生成一次低分辨率的模糊版本，标签在自己的区域里绘制这张模糊图，再叠加 chip 色。
  - 看大图时的背景同理，使用预先生成的模糊图。

### 3.6 图标

- 线性图标：线宽 1.75，圆角端点，24 网格。
- 同一个含义只用一个图标：
  - 侧边栏开关和详情栏开关都用“面板”图标（矩形加一条竖线，竖线在哪一侧，就代表哪一侧的栏）；
  - 关闭用 ×，下载用向下箭头，复制链接用链环，设为背景用“图片”图标。
- 平台图标：20 × 20 的圆角方块，写平台缩写（p、f、G、F、P、Pw、X、微、V）。选中时反色。

glass 底，1px edge 描边，圆角 12，内边距 8；菜单项高 34，圆角 4（同心：4 + 8 = 12）。

出现时从触发按钮的方向缩放（0.96 → 1）加淡入，使用第 5 章的弹簧曲线。点击外部或按 Esc 关闭，**面板里不放“关闭”按钮**。弹出面板永远在最上层，不能有任何控件画在它上面；它的毛玻璃与其他悬浮层相同（第 3.5 节），透过它不能看清下面的文字。

1px div 色，两端各缩进 14，与上下内容的距离相同（侧边栏里都是 8）。

### 4.9 溢出：淡出与滚动（所有长文本、标签行、缩略条、页码条通用）

1. **不用省略号，不硬裁。** 内容超出时，在超出的一侧做 22～36 的淡出。
2. **只在该出现的时候出现**：内容在最左端时，左侧不淡出；在最右端时，右侧不淡出；没有溢出时两侧都不淡出。
3. **淡出的出现和消失都要过渡**，跟随滚动位置连续变化，不能突然出现或消失。
4. **标签行、缩略条、页码条**：鼠标悬停时，在有更多内容的一侧淡入一个小箭头（标签行 20 × 20；缩略条 24 × 40），点击后平滑滚动一段。到头的一侧不显示箭头。
5. **标题、作者名**：没有箭头。鼠标悬停 0.3 秒后开始来回滚动：
   - 速度约 33 像素 / 秒，两端各停顿约 12% 的时间，曲线 ease-in-out；
   - 淡出跟着滚动位置变化；
   - 鼠标移开时，文字沿弹簧曲线（第 5.1 节）滚回起点，淡出同步恢复，**不能瞬间复位**。

## 5. 动效

动效是这个产品的核心体验之一。用户的要求：**像 iOS 一样优雅；同一张卡片在不同布局之间要“移动”过去，而不是消失再出现；所有动画都能中途打断。**

### 5.1 曲线与时长

- **唯一的运动曲线：临界阻尼弹簧**（无回弹）。公式为 x(t) = 1 − (1 + ωt)·e^(−ωt)，ω 约 18/秒，约 0.5 秒稳定。
- 位置、大小、裁切、缩放、滚动都用这条弹簧。**用物理模拟实现（保存当前值和速度）**，不要用固定时长的补间。
- 只有颜色和透明度的变化（悬停、淡入淡出），用 0.22 秒的 ease-out。
- 不同模块不要各自定义曲线。需要更快或更慢时，只调整 ω，并在本文登记。

### 5.2 中途打断

任何动画在进行中都可以收到新的目标（例如打开大图到一半又点了关闭）：

1. 从**当前的视觉位置和当前速度**出发，走向新目标；
2. 仍然使用同一条弹簧曲线；
3. **不要把原动画倒放**。倒放会让回程变成“先快后慢”的反向曲线，看起来很怪。

用弹簧物理模拟实现，天然满足以上三点。

### 5.3 布局变化：共享元素移动

触发场景：
- 拖动大小滑块；
- 侧边栏展开 / 收起；
- 切换分栏；
- 窗口尺寸变化；
- 筛选或排序后，仍然留在结果里的作品；
- 新作品实时插入。

规则：

1. **同一张卡片从旧位置移动到新位置**，同时缩放到新尺寸。封面、角标、图片上的标签随卡片一起等比缩放和平移。
2. **文字逐字移动**：标题和作者名按字形拆开，每个字从旧位置移动到新位置；字号或字间距变化时，每个字各自缩放、各自移动。
   - 字符串相同的，按字符序号一一对应；
   - 字符串不同的（比如数量变了），不同的那几个字交叉淡入淡出。
3. 淡出遮罩（第 4.9 节）的位置随新宽度一起过渡。
4. 离开的卡片原地淡出并缩小到 0.96；新出现的卡片原地淡入并从 0.96 放大。
5. 大量卡片同时移动时，**只动可见区域内的卡片**，可见区域以外的直接到位。

### 5.4 翻页

- 旧页的卡片淡出；新页的卡片从翻页方向滑入 24 并淡入，每张卡片错开 12 毫秒，总错开不超过 200 毫秒。
- 页码条上的页码带同步平滑滑动，淡出区域同步过渡。

### 5.5 悬停：照片散开

鼠标停在一个**有两页或以上**的作品上时：

1. 封面“下沉”：缩小到 0.90，阴影加深。
2. 背后像散落的照片一样探出这个作品的另外几页，**最多 3 张**：
   - 如果封面本身就是第 1 页，探出第 2～4 页；
   - 如果封面不属于作品内容，探出第 1～3 页。

   | 照片 | 平移（占卡片边长） | 旋转 | 缩放 |
   |---|---|---|---|
   | 第 1 张 | (−19%, −10%) | −9° | 0.80 |
   | 第 2 张 | (18%, −13%) | 8° | 0.78 |
   | 第 3 张 | (2%, −21%) | −2° | 0.76 |

3. 每张错开 30 毫秒出现；悬停的卡片层级提到最上面，允许照片越过卡片边界。
4. 只有一页的作品没有这个效果。
5. 鼠标停留 120 毫秒后才触发，避免划过网格时一片闪动；鼠标开始停留时就预加载这几张缩略图。
6. 移开时沿弹簧收回；中途移开或移回，都从当前位置继续。

### 5.6 打开和关闭看大图

**打开**：整张作品卡片放大成看大图的界面。

1. **封面就是第 1 页时**：封面直接变成大图。同时做两件事：
   - 缩放和平移：从卡片的位置和尺寸，到大图在看图区域里的最终位置和尺寸；
   - 裁切：从卡片的方形裁切，逐渐展开到图片完整的比例；圆角从 6 变到 0。
2. **封面不属于作品内容时**：真正的第 1 页从封面背后滑出来。
   - 如果鼠标正停在卡片上，它就从散开照片的位置出发；
   - 然后同样缩放、平移、展开裁切，变成大图；
   - 这是一条连续的路径，由同一个弹簧驱动。
3. 同时，封面、这张卡片的标题 / 作者 / 标签、其他卡片都**原地淡出**。看大图的背景淡入。顶栏从上方、底栏从下方、详情栏从右侧依次滑入，各错开 40 毫秒。

**关闭**：沿同样的路径回到卡片当前所在的位置。关闭时重新查询卡片位置，因为期间布局可能变了。
- 封面就是第 1 页：直接缩回封面。
- 封面不属于作品内容：大图缩回到封面背后，同时淡出；封面淡入。
- 其他卡片和文字原地淡入。

**中途打断**：打开到一半点关闭，或关闭到一半又点开，都按第 5.2 节从当前状态转向。

### 5.7 在看大图里换作品

1. 在看大图里切到别的作品时，大图沿切换方向滑动过去。
2. **背后的网格同步更新**：切出去的作品在网格里重新淡入，切到的作品在网格里原地淡出。这样关闭时，大图能准确回到新作品的卡片，不会闪一下。
3. 如果切到的作品不在当前可见范围或不在当前页，网格在背后悄悄滚动或翻到它所在的位置。实在无法定位时，关闭动画改为缩小并淡出到屏幕中央。

### 5.8 其他动效

| 场景 | 动效 |
|---|---|
| 侧边栏展开 / 收起 | 宽度沿弹簧变化。文字和分组标题 0.22 秒淡出 / 淡入。图标、分割线、状态点位置不动。内容区跟着连续重排（按第 5.3 节）。收起按钮随收起过程淡出 |
| 收起后悬停画廊图标 | 画廊图标与侧边栏开关图标交叉淡入淡出 |
| 看大图翻页 | 沿方向滑动；触屏时跟手，松手后弹簧归位 |
| 缩放 | 按钮 / 滑块 / 滚轮缩放都沿弹簧到目标；双指缩放 1:1 跟手；超出范围时有阻尼，松手回弹 |
| 详情栏开关 | 详情栏从右侧滑入 / 滑出；看图区域和图片同时按新尺寸重新适应 |
| 左右翻页按钮 | 打开看大图时显示约 1.8 秒后淡出；鼠标进入看图区域左右两侧 200 以内时，**两个按钮同时**淡入；离开后淡出 |
| 底栏缩略条 | 当前页永远在底栏正中，换页时整条平滑滑动 |
| 分栏中换作品 | 右侧大图交叉淡入淡出，并沿作品顺序的方向轻微滑动 |
| 主题切换 | 0.3 秒。**整个界面层交叉淡化**：旧主题的界面画在上面淡出，新主题的界面在下面。不要逐个颜色插值，否则中途文字色和底色会变成同一种灰，文字消失。作品图片不参与过渡 |
| 新作品实时出现 | 在第 1 页且用户闲置时，新卡片从 0.96 淡入放大，其他卡片按第 5.3 节让位 |

### 5.9 减少动态效果

设置里的“减少动态效果”打开，或者系统设置了减少动态效果时：
- 所有移动和缩放改为 0.2 秒以内的淡入淡出；
- 不做照片散开；
- 标题不再来回滚动，只保留淡出。

### 6.2 侧边栏

**展开时（宽 240）**，从上到下：

1. **标题区**（高 50）：
   - 左边是画廊图标和品牌字“画廊”；
   - 右边是侧边栏开关按钮（面板图标，竖线在左）。
2. 分割线。
3. **“平台”**分组标题，下面是 9 个平台：pixiv、pixivFANBOX、Gank、Fantia、Patreon、Pawchive、X、微博、Venera。每项依次是：平台图标、名称、右侧用 faint 色写作品数。作品数用千位分隔符（5,161），选中时也保持 faint 色、常规字重、同一位置，只有名称加粗。
4. 分割线。
5. **“全部文件”**分组标题，下面是配置好的文件目录。这部分直接浏览磁盘，不经过数据库。
6. 空白。
7. 分割线，下面是连接状态：
   - 在线：绿点 +“已连接 · 5 分钟前更新”。时间写法：1 分钟内“刚刚更新”；1 小时内“N 分钟前更新”；24 小时内“N 小时前更新”；更早写日期“10 月 1 日更新”。分隔符一律用“·”；

- 开关按钮随收起过程淡出。
- 鼠标悬停在画廊图标上时，它与开关按钮图标交叉淡入淡出；点击展开。
- 收起状态记在本地。

### 6.3 顶栏

**第一行**（高 50，左右留白 8，控件间距 8）：

- 设置按钮。

**第二行**（高 42）：
- 分段控件“作品 5,160 | 作者 42”：数字是**当前结果**的数量，搜索、标签和筛选都会改变它；数字用 faint 色和千位分隔符。作者数量无法按标签或“图片 / 视频”筛选时，这两种筛选生效期间“作者”后面不写数字，不要显示一个不准的数；
- 标签按钮：“标签 全部 ▾”，打开标签面板；宽度随文字，左右内边距 12，末尾一定有 ▾；
- 分段控件“全部 | 图片 | 视频”；
- 空白；
- 排序按钮（外观同标签按钮，文字后带 ▾）：
  - 作品：最新发布、最早发布、标题 A→Z、标题 Z→A、文件夹名 A→Z、文件夹名 Z→A；
  - 作者：名称 A→Z、名称 Z→A、最近更新、最早更新、作品最多、作品最少；
- 大小滑块；
- 分栏按钮（只在电脑上显示）。

筛选条件、排序、页码都要写进网址，刷新或分享后能恢复。**保持现有的稳定网址**（`/p`、`/f`、短链），这是必须保留的兼容。

### 6.4 大小滑块（替代原来的三种布局）

- 一个分段滑块，从左到右共 6 档：列表、小、较小、中、大、特大。
- **网格的列数按“目标卡片宽度”自动计算**，不写死列数：
  - 小 ≈ 140、较小 ≈ 180、中 ≈ 220、大 ≈ 280、特大 ≈ 360；
  - 在 1440 宽的屏幕上，大约分别是 8、6、5、4、3 列。
- 切换档位时按第 5.3 节做共享元素移动。
- 列表形态每行依次是：64 × 64 缩略图、标题和作者、标签行、发布日期：
  - 四列都以缩略图为准垂直居中；
  - 列宽固定：标题和作者占内容区的 45%，溢出时在列内淡出；标签行从固定的列开始，溢出时按第 4.9 节淡出；日期右对齐，距右边 16；
  - 日期写成“2021-02-15”。
- 选择的档位记在本地。手机上只提供列表、较小、中三档。
- 以后可能增加“形态”（方形裁切 / 按原比例排列），见第 9 章。

### 6.5 作品卡片

- **封面**：方形裁切，圆角 6。
- **角标**（内缩 4，圆角 2，毛玻璃）：
  - 左上：R-18、AI；
  - 右上：页数（多页作品），或视频时长（视频作品）。
- **标签行**：在封面底部，内缩 4，按第 4.5、4.9 节处理溢出。
- **封面下方**：标题（13 号，500）、作者（12 号，muted）。溢出时淡出，悬停时来回滚动。
- **点击封面**：打开看大图（分栏模式下是选中这个作品）。**点击作者名**：进入作者页。**点击标签**：按标签筛选。
- 隐私模糊打开时，封面和图片上的标签都模糊处理；悬停时不解除。
- 悬停效果按第 5.5 节。

### 6.6 页码条

放在内容区底部居中，毛玻璃，分成两块，两块之间间距 8。

1. **翻页块**：第一页、上一页 │ 页码带 │ 下一页、最后一页。
   - 页码带宽约 310，当前页尽量居中，到两端时不再居中；页数少、放不满时，页码带收窄到正好放下所有页码；
   - 页码带两侧按第 4.9 节淡出；
   - 翻页时整条页码带平滑滑动；
   - 页码在四位数以上时自动加宽；
   - 在第一页 / 最后一页时，对应的两个按钮禁用。
2. **跳页块**：“第 [12] / 108 页”。
   - 点击中间的数字，**只有这个数字**原地变成输入框，“第”和“/ 108 页”保持不动；
   - 回车跳转，Esc 或点击外面取消；
   - 超出范围的数字自动取最近的有效页。
3. 只有 1 页时不显示页码条。
4. 页码带要能承载上千页。自绘时只绘制可见的页码，整条页码带是连续的，**不能出现原来那种为了性能而切换成“虚拟页码”的跳变**。

### 6.7 看大图

打开和关闭的动画见第 5.6 节。布局如下：

```
┌──────────────────────────────────────────────────────────────┐
│ [×]                                      [下载] [复制链接] [详情栏] │  顶栏 50，占满宽度
├──────────────────────────────────────────────┬───────────────┤
│                                              │ 详情栏 240      │
│            看图区域（永远是深色）                 │ 标题            │
│   [‹]            图片（按比例最大化）          [›] │ 作者            │
│                                              │ 平台 / 发布 /    │
│                                              │ 页数 / 位置      │
│                                              │ 标签            │
│                                              │ 简介            │
│                                              │ ─────────────── │
│                                              │ [设为背景]       │
├──────────────────────────────────────────────┴───────────────┤
│ 3 / 12   ‹ ░ 缩略图 │ 缩略图 [当前] 缩略图 │ 缩略图 ░ ›   [适应 100% − ━━ +] │  底栏 64，占满宽度
└──────────────────────────────────────────────────────────────┘
```

1. **顶栏**（占满宽度，高 50，控件间距 8）：
   - 最左：关闭；
   - 最右，从右往左依次是：详情栏开关（面板图标，竖线在右）、复制链接、下载；
   - **顶栏不写标题**。
2. **详情栏**：
   - 夹在顶栏和底栏之间，靠右，宽 240；
   - 收起时完全隐藏，不留窄条；
   - 内容依次为：
     - 标题（16 号，600；换行时英文按单词断开，不能把一个单词拆成两行）；
     - 作者（头像 + 名称 + 账号，点击进入作者页）；
     - 平台 / 发布日期 / 页数 / 来源 / 位置：来源是链接，点击打开原网页；位置过长时淡出，点击即可复制，悬停时提示“点击复制”。位置显示稳定的逻辑路径（例如 /p/pixiv/作者/作品），不显示服务器上的绝对路径；
     - 多页作品在信息行下面放一个次要按钮“查看全部 48 页”，进入作品的全部页；
     - 标签（可以换行，点击筛选）。样式按第 4.5 节“其他地方”：高 22，圆角 4，tag-bg 底（不能只写文字）；
     - 简介（作品正文，现在的前端没有显示，这次要显示）。纯文本显示，正文里的网址变成可点击的链接，在新标签页打开；内容长时详情栏整体滚动；
   - 底部只有一个按钮：“设为背景”，次要按钮样式（tag-bg 底，和“查看全部 48 页”一样）。
3. **看图区域**：
   - 顶栏、底栏、详情栏之间的区域，**任何主题下都是深色（stage）**，并铺一层当前图片的模糊版本；
   - 图片在这个区域里按比例最大化显示：一个方向贴边，不裁切，允许位于左右翻页按钮下方；
   - 视频使用播放控件，支持字幕。
   - **原图加载中**：先显示放大的缩略图，不画任何占位块；超过 1 秒还没加载完，在看图区域底边显示一条 2 高的细进度条。
   - **原图加载失败**：看图区域中央一块毛玻璃面板（glass 底，圆角 12，内边距 16）：一句“加载失败：{原因}”+ [重试]。不要把文字直接画在图片上。
4. **左右翻页按钮**：圆形，毛玻璃（第 3.5 节）；按第 5.8 节自动显示和隐藏。
5. **底栏**（占满宽度，高 64）：
   - 左：“3 / 12”（当前页 / 本作品页数）；
   - 中：缩略条。**当前页永远在底栏的正中间**。缩略条里除了本作品，还放前后各两个相邻的作品；作品之间用高 40 的分割线隔开；本作品的缩略图比相邻作品的更亮。缩略条碰到左右两侧的控件时，按第 4.9 节淡出和显示箭头（箭头切换到上一个 / 下一个作品）；
   - 右：五段式缩放控件“适应 | 100% | − | 滑条 | +”（控件组，第 4.3 节的规格）。
6. **快捷键**：
   - ← / →：翻页；
   - Shift + ← / →：上一个 / 下一个作品；
   - Esc：关闭；
   - + / −：缩放；
   - 0：适应；
   - I：详情栏开关；
   - H：隐藏 / 显示界面。
7. **触屏**：
   - 左右滑动翻页；
   - 双指缩放；
   - 双击在适应和 2 倍之间切换；
   - 放大后拖动平移。
8. 浏览器的“后退”关闭看大图，并回到原来的位置。
9. **隐藏界面（保留原有的“隐藏工具”功能）**：按 H 或单击图片（没有拖动），顶栏、底栏和详情栏一起滑出，只留图片；再按一次恢复。状态记在浏览器本地。隐藏时看图区域扩展到整个窗口。

### 6.8 分栏（仅电脑，宽度 ≥ 1280）

- **怎么进入（按用户原话）**：顶栏第二行的分栏按钮是一个开关，打开后，“点击作品”的行为从“打开看大图”变成“用分栏打开”：点击卡片时，作品网格按第 5.3 节平滑缩到左半边，右半边显示这个作品。点右边顶栏的关闭，网格恢复全宽，开关保持打开。
- 作品网格缩到左半边，右半边用**和看大图相同的结构**：
  - 顶栏：最左关闭（退出分栏），最右依次是复制链接、下载，**没有**详情栏开关；
  - 看图区域（深色）；
  - 底栏：页码、缩略条、缩放控件。
- 点击左边的卡片，右边切换到这个作品；选中的卡片有 2px fg 描边（外扩 2px）。
- 右边顶栏或双击图片，可以打开完整的看大图。

### 6.9 其他页面

| 页面 | 内容 |
|---|---|
| 作者列表 | 作者卡片网格：封面拼图（最近 3 部作品）、名称、账号、作品数、最近更新时间。支持搜索、排序、大小滑块。拼图上不放页数角标，作品数只写在卡片下方。**拼图**：方形，左边一张占 2/3 宽、全高；右边两张上下排列；三张之间间距 2，外圆角 6，每张都居中裁切，不重叠、不偏移。只有 1～2 部作品时用 1 张或左右 2 张；没有作品时显示作者图标占位（faint 色） |
| 作者页 | 顶部一行：头像、名称、账号、作品数、来源链接；下面是这个作者的作品网格，筛选和排序与平台页相同 |
| 作品的全部页 | 从详情栏或网址进入：这个作品所有页的网格，点击任意一页打开看大图 |
| 全部文件 | 顶栏第二行只保留“全部 / 图片 / 视频”、排序和大小滑块，不显示“作品 | 作者”和“标签”（文件没有这两种概念）。路径（每一级都可以点击）、按名称搜索、正序 / 倒序、全部 / 图片 / 视频；文件夹和文件用同一种卡片；文件按自然顺序排列（1、2、10）；搜索结果不完整时，在结果顶部说明“结果不完整：部分目录无法读取” |
| 搜索结果 | 顶栏第二行下方显示当前条件：关键词和标签都是可以单独移除的标签，例如“雨 ×”“标签：风景 ×”；再加结果数量 |
| 标签面板 | 弹出面板：搜索框 + 标签列表（标签名和作品数），每次显示 40 个，可以继续加载；选中的标签在顶部，可以清除。列表项和菜单项一样：高 34，标签名左对齐，作品数右对齐、faint 色，不要居中 |
| 设置面板 | 主题（跟随系统 / 深色 / 浅色）；背景（纯色 / 作品图片，选了图片时显示缩略图、“更换…”和“背景淡化”滑块）；隐私模糊；隐藏没有可看内容的作品（默认开）；减少动态效果；每页数量（24 / 48 / 72 / 96 / 120）。全部保存在浏览器本地 |

**背景图**：
- 可以在设置面板里从画廊中选一张作品，也可以在看大图的详情栏里点“设为背景”；
- 保存在浏览器本地；
- 显示时在上面叠一层**当前主题的页面底色（bg）**，滑块叫“背景淡化”，范围 50%～90%，默认 66%，滑块右边显示百分比。深色主题下背景图变暗，浅色主题下变淡。
- **设置面板里的背景一行**：
  - 第一行：“背景”+ 分段控件“纯色 | 作品图片”，选了哪个就高亮哪个，不要把“更换…”放进这个分段控件；
  - 选了作品图片时，下面一行：48 × 48 缩略图 + [更换…]；再下面一行：“背景淡化”滑块和百分比；
  - 设置面板里的所有分段控件（主题、每页数量、背景）都用第 4.3 节的标准样式（field 底的容器）。
- **选择背景面板**：标题左边有返回按钮“‹”，点它或按 Esc 回到设置面板；点外部关闭全部面板。当前正在用的背景图带选中描边。

### 6.10 页面状态

| 状态 | 表现 |
|---|---|
| 加载中 | 卡片位置显示占位块，带轻微的明暗呼吸。不显示转圈，也不写“正在打开”等文字 |
| 空 | 内容区中央一个大图标 + 一句话：平台为空时“这个平台还没有作品”，文件夹为空时“这个文件夹里没有图片或视频”。图标 48，faint 色；文字 14 号，fg2 色，常规字重；按钮（如果有）在文字下方 12 |
| 筛选后为空 | “没有符合条件的作品” + [清除筛选] |
| 网址里的筛选条件无效 | “网址里的筛选条件无法识别” + [清除筛选] |
| 出错 | 内容区中央：“加载失败：{原因}” + [重试]。原因用一句人话，例如“服务没有响应” |
| 网址失效 | “找不到这个作品，它可能已被移动或删除。” + [返回] |
| 新内容 | 内容区顶部中央出现毛玻璃小条“有 12 个新作品 · 刷新”。在第 1 页且用户闲置时自动刷新（按第 5.8 节）；看大图时不打扰 |

加载中、空、出错时**不显示页码条**（没有页可翻）。这些状态下内容区就是普通的页面底色，**不要叠任何遮罩**。整个应用第一次显示的画面（包括加载中）就要用用户保存的主题，不能先闪一下浅色再变深色。

### 6.11 手机（iPhone）与平板（iPad）

**手机**：
- 侧边栏变成从左侧滑出的抽屉，内容和样式与电脑版相同。
- 顶栏第一行：侧边栏按钮、路径、搜索图标（点开后搜索框展开占满这一行）、设置。
- 顶栏第二行的控件放在一条可横向滑动的条里，两端按第 4.9 节淡出。
- 网格 2～3 列；页码条缩成“‹ [12] / 108 ›”。
- 看大图全屏：
  - 顶栏相同；
  - 详情栏改为从底部拉起的面板；
  - 底栏只保留缩略条，缩放用手势。
- 没有分栏；悬停效果改为长按。
- **层级**：侧边栏抽屉打开时在最上层，下面的内容盖一层 40% 黑色遮罩，新内容提示条、搜索条件标签等都在遮罩下面。看大图里拉起详情面板时，左右翻页按钮隐藏。

**平板**：
- 横屏：与电脑相同，侧边栏默认收起。**不提供分栏**（用户说过分栏“仅 PC 视图”；分栏只在宽度 ≥ 1280 时出现，第 6.8 节）。

## 7. 管理端

窗口默认 1280 × 800，最小 960 × 640。沿用网页端的全部设计系统：同样的侧边栏（品牌字“画廊管理”）、分割线、控件、同心圆角、动效和文案规则。关闭窗口时隐藏到托盘；托盘菜单保持现状。

侧边栏只有 4 项，每项都有图标（和网页端侧边栏一样，图标 + 名称）：

| 页面 | 使用频率 |
|---|---|
| 更新图库 | 每天 |
| 访问 | 常用 |
| 设置 | 偶尔 |
| 排查 | 出问题时 |

侧边栏底部显示服务状态：“服务运行中 · 端口 18104”，或“服务已停止”。顶栏：页面标题，右侧一个“打开画廊”按钮。

### 7.1 更新图库（首页）

1. **服务行**（面板）：
   - 状态点 +“服务运行中”；
   - 地址（等宽字体）+ 复制按钮；
   - “已运行 3 天 2 小时”；
   - 右侧：[重启] [停止]。服务停止时换成 [启动]。
2. **更新图库**（面板）：
   - 标题右侧写“上次更新 今天 09:12 · 用时 4 分 12 秒”；从没更新过时写“还没有更新过”；
   - 平台选择：9 个平台标签，一行 5 个，每个都有勾选框、平台名和作品数；右上角有“全选”“清空”；默认全选，选择记在本地；
   - 主要按钮的文字跟着选择变化：全选时是“更新全部平台”，否则是“更新所选的 3 个平台”，一个都没选时禁用并显示“先选择平台”；
   - 次要按钮：“全部重新扫描…”，需要确认，见第 7.7 节。
3. **上次结果**（面板）：
   - “新增 36 · 更新 4 · 移除 1 · 作品总数 8,859”；
   - 下面列出需要处理的问题，每条一行：图标 + 一句话 + “查看 ›”（进入排查页的对应问题）。

**正在更新时**，“更新图库”面板变为：

- 标题“正在更新”，右侧“已用时 02:14”；
- “第 3 / 9 个平台 · Gank”，右侧写百分比；下面是进度条；
- 已检查 1,204 / 5,160 · 新增 12 · 更新 1 · 移除 0；
- 平台标签显示各自状态：已完成（绿勾 +“+8”）、进行中、等待、未选择；
- [停止]：不需要确认，停在当前作品完成之后；
- 更新完成后自动生效，**不需要手动重启，也不需要确认发布**。

### 7.2 访问

- 顶部一行：
  - “封禁功能”开关；
  - 右侧时间范围分段控件（今天 / 7 天 / 30 天）。
- 表格：地址（等宽）、客户端（浏览器 / Venera / 本机）、请求数、错误数（非零时 err 色）、最近访问、操作。
- **封禁功能开关立即生效**，不经过设置页的保存条。开关样式和网页端一样（第 4.6 节）。
- 所选时间范围内没有记录时，表格位置显示“这段时间没有访问记录”。
  - 操作：[封禁]，或“已封禁”标记加 [解除]；
  - 本机和代理只显示“本机”标记，不能封禁；
  - 封禁和解除都不需要确认，可以随时撤销。

### 7.3 设置

分三组面板：

1. **平台目录**：9 行，每行依次是平台名、路径（过长时**左侧淡出**，保留路径末尾）、[更改…]（打开系统的选择目录对话框）。
2. **全部文件**：已配置的目录，每行有名称、路径、[更改…]、[移除]；下面是 [＋ 添加目录]。
3. **网络**：
   - 谁能访问：仅本机 / 局域网 / 公网；
   - 端口；
   - 对外地址（Venera 使用）；
   - “高级”折叠区：允许的 Host、Origin、短链。

**保存方式**：保存条**只出现在设置页**，其他页面不显示。有改动时，底部浮出一条保存条“2 项改动未保存”，需要重启时再加一句灰字“保存后会重启服务，正在浏览的人需要刷新页面”，右侧是 [放弃] [保存并重启]。保存本身就是确认，不再弹框。路径校验失败时，在对应行下方直接显示原因。

### 7.4 排查

- **左边：日志**。
  - 顶部：级别分段控件（全部 / 警告 / 错误）、搜索框、打开日志目录按钮；
  - 内容：时间、级别、一句中文说明；路径写成“平台 / 作者 / 作品”。**不要直接显示 JSON**：例如一次更新结束写成“Fantia 增量更新完成：新增 0 · 更新 0 · 移除 0 · 用时 8 秒”。点击某一行可以展开它的原文（等宽字体），再点收起；
  - 默认跟随最新内容；
  - 本机管理端直接显示日志原文，不需要“显示原始日志”的确认。
  - 没有日志时显示“还没有日志”。
- **右边：三个小工具**。
  - **检查图库**：写明“上次检查 9 月 28 日 · 发现 3 个问题”，按钮 [开始检查]、[查看问题]。问题列表可以按类型筛选，每条都能“在资源管理器中显示”，也能导出。
  - **运行环境**：ImageMagick、FFmpeg、9 个平台目录是否可读，每项一行，用对勾或叉表示；按钮 [重新检查]。
  - **缓存**：写明“缩略图缓存 1.2 GB，清理后会在浏览时重新生成”，按钮 [清理缓存…]，需要确认。需要停止服务的话，由程序自动停止、清理、再启动，不要让用户手动操作。

### 7.5 从界面上去掉的功能

以下功能从管理端界面上删除，并删掉对应的界面代码：
- 数据版本列表，以及校验、发布、回滚、保守清理的预览和执行；
- 实时库重置；
- 诊断结果的 JSON 展示；
- 扫描进度里的内部指标（吞吐、RSS、Heap、metadata 分类、磁盘 I/O 参数）；
- 作者范围扫描的高级区；
- 编号式导航、各页顶部的说明段落和安全声明。

后端机制（数据版本、自动清理等）是否保留，由你按技术判断决定，不需要问用户。原则是：用户看不到、也不需要操作的东西，**自动完成**。

### 7.6 管理端的空、加载、出错状态

- 服务未启动：更新图库面板禁用，服务行显示 [启动]。
- 首次使用、还没有配置目录：首页只显示一个引导面板“先设置平台目录” + [去设置]。
- 任何操作失败：在操作所在的面板内显示“{操作}失败：{原因}” + 可以做的操作。不弹窗。

### 7.7 需要确认的操作（全产品只有这几项）

| 操作 | 确认内容 |
|---|---|
| 全部重新扫描 | “全部重新扫描会重新读取所有作品，通常需要几十分钟。期间画廊可以正常浏览。” [开始] [取消] |
| 清理缓存 | “缩略图缓存会被删除，浏览时会重新生成，这段时间图片加载会变慢。” [清理] [取消] |
| 离开有未保存改动的设置页 | “有 2 项改动未保存。” [保存并重启] [放弃改动] [取消] |

确认框使用弹出面板样式（第 4.7 节），默认焦点在“取消”上。**网页端没有任何确认框。**

## 8. 技术、性能、进度与发布

### 8.1 技术（已定）

- **网页端**：WasmJS 自绘，使用 CanvasKit（Skia，WebGL2），由 JS 驱动。
  - 原生 DOM 只用来搭桥：输入框和输入法、读屏的语义信息、图片的右键菜单（用真实的 `img`）、视频播放。
  - 首次加载慢一些可以接受。
- **管理端**：原生表单 + Electron，**不自绘**。与网页端共用同一套颜色、尺寸、圆角和动效变量，视觉和交互必须一致。
- **字体**：全部随程序附带，不请求外部 CDN。
  - Noto Sans SC：界面字体，分包按需加载；
  - Outfit：只用于拉丁字母；
  - JetBrains Mono：管理端的地址、路径和日志；
  - Noto Color Emoji：可见文字里出现表情时才加载。
- **自绘必须保证的浏览器能力**：
  - 输入法和剪贴板：搜索框、跳页输入框、管理端的输入框都支持中文输入法；复制链接、复制位置能用。
  - 无障碍：键盘操作完整（Tab 顺序、焦点样式、快捷键），为读屏提供语义信息。
  - 网址与前进后退；图片能“另存为”；高分屏清晰；触屏手势。
  - 不禁用页面缩放。
- **后端**：可以随开发需要调整，但不能破坏附录 A 的兼容约束。
- **已作废的方向**：整体换成 Compose Multiplatform + Miuix；Fluent 风格的改造。

### 8.2 性能目标与测法

| 场景 | 目标 |
|---|---|
| 120 张卡片（带毛玻璃标签）滚动 | 电脑、iPad、iPhone 上 60 帧 |
| 拖动大小滑块（全部可见卡片同时移动） | 不掉帧或偶尔掉 1 帧 |
| 打开 / 关闭看大图 | 不掉帧 |
| 看大图翻页（原图已缓存） | 50 毫秒内开始动画 |
| 页码带（1,080 页） | 滑动流畅，没有跳变 |

**测法**：

- 在沙盒里用合成数据测；测量时不同时录屏或截图。
- 电脑上每个场景测 3 次，每次约 3.3 秒。

**怎样算达标**：

- 帧率类场景：每次测量里**错过的帧不超过 2 个**，并且**没有超过 50 毫秒的停顿**（即没有连续错过 3 帧）。
- 翻页：从按键到动画开始不超过 50 毫秒。
- 页码带：同时满足帧率类的标准，并且没有跳变。

**性能问题按问题报告处理，不是停工的关口**：

- 发现退步就记录、找原因、修复。
- 一时修不好的，在发布说明里写明影响和计划，其他工作照常进行。
- 改了可能影响性能的代码，要在同一台机器上测改动前后。
- 手机和平板：只有用户愿意时才做真机测速，需要用户做的操作不超过 3 步。**没在真机上测过的设备，不写“达标”。**

## 附录 A：现有产品的约束

来源：开发者在重新设计之前整理的《画廊系统现状报告》中，有用户对话依据的部分，以及用户在本次重新设计中的确认。这些约束在重新设计之后仍然有效。

### A.1 产品定位

**网页端**：

- 读者从平台、作者、标签或搜索找到本地作品，查看图片、多页作品和视频。刷新、分享链接、从看大图返回列表后，都要回到原来的位置。
- 主要使用者是用户本人和少量可信的读者。
- 不做：账号、上传、站内发布、审核、付费订阅、评论，以及编辑磁盘上的文件。

**管理端**：

- 托管者在 Windows 本机控制后台服务：维护目录设置、更新图库和检查图库、查看日志、处理失败。关闭窗口后，服务继续在托盘里运行。
- 不做：编辑 metadata、重命名或删除源作品、账号和权限、替代下载器、通用文件管理器。

### A.2 用户明确过的决定

1. 以磁盘上的文件为准，metadata 只用来补充信息。作品不能因为 metadata 有问题而消失。
2. 平台固定为九个（包括 Venera 下载库）；“全部文件”（直接浏览磁盘）独立存在。
3. 平台选择放在最上层，可以多选。
4. 普通的增量更新步骤要少，不要层层确认；完成后自动生效，不需要手动重启。
5. 默认隐藏“去掉封面后没有可看内容”的作品，可以在设置里关掉。
6. 生产域名、localhost、Venera 兼容、托盘后台和正式 exe 入口，都要继续可用。
7. 管理端要保留日常真正需要的能力，不能只剩流程验证（具体范围见第 7 章）。
8. 打开图片要从缩略图连续放大过去（第 5.6 节）。
9. Fluent 风格的改造已经整体撤回，不要再用。
10. 设计面向任务、少重复说明、保持信息密度，适配不同屏幕，照顾无障碍。

### A.3 “好用”的具体标准（来自过去的问题反馈）

- 更新图库后刷新页面，不需要手动清理网址尾巴；
- 筛选结果准确；
- 视频有封面，能播放；
- “全部文件”入口容易找到；
- 从看大图返回时，回到原来的位置；
- 普通更新步骤少，结果自动生效。

### A.4 技术约束

1. 后端 API 可以随开发调整，但以下几项必须保持能解析，或者明确地处理失效：
   - Venera 的安装源和已收藏的 ID；
   - 旧的兼容 GET 路由；
   - 稳定的 `/p`、`/f` 分享路径；
   - 短链的目标。

   不能把临时的整数 ID 当作永久 ID 使用。
2. Electron 的 IPC 只允许本地可信的管理页面使用，方法和操作用固定白名单；页面不能直接读 SQLite、执行任意命令或浏览任意磁盘。
3. 正式宿主是 Windows。
4. 构建入口：`npm run check`、`npm run check:electron`、`npm test`、`npm run build`。
5. 生产安装里的实例数据不能随意覆盖。

### B.4 2026-09-30 · 对设计画布方向 B（“展墙”）的意见

说明：第 2 条（三横线按钮放在画廊图标左侧）后来被 B.5 第二部分的第 1 条取代：开关改用面板图标，放在侧边栏标题区的右侧。

> 我喜欢 B 设计，侧边栏和顶栏都紧贴外边缘是最好的，小圆角也对胃口，邮件式分栏的设计也不错，灯箱的设计我看了，也不错
> 接下来的建议都针对当前你给我准备的 B 设计：
>
> 1. 侧边栏画廊、平台、文件与连接状态之间需要有比侧边栏宽度略小的分割线，上半部分的分割线距离上下内容等距，下半部分的分割线复用上半部分的距离，但是放在连接状态上面
> 2. 用于管理侧边栏显隐的三横线按钮应该放在画廊和图标的左侧，侧边栏收起的状态应该是只隐藏侧边栏的文案，保留画廊图标、各平台图标、分割线以及连接状态图标，用户鼠标悬浮在画廊图标上时，画廊图标过渡为三横线，点击展开

> 6. 侧边栏我已经观察到一个粗糙的地方，当一个选项被选中时，聚焦高光和选项内容之间应该存在设计好的间距（如果都是圆角矩形的话还需要考虑圆角圆心）
> 7. 标签会经常遇到单个超长标签以及标签总量比较多的情况，大部分情况都是超出单行宽度的，因此最终可能需要做一点超界裁切，但我建议不要硬裁，也不要把文字变成省略号，而是做一个淡出，最好还能加两个鼠标悬浮后自动出现的小箭头用于滚动，注意当标签已经在最左时隐藏左箭头，最右同理，淡出也一样，只在应该出现的时候出现；相同情况的还有标题以及可能的作者文字，但这俩不提供小箭头滚动，而是鼠标悬浮自动来回滚动，淡化的出现形式同标签

> 9. 页码条滚动条左右两边的淡化记得加，类似标签的

### B.5 2026-09-30 · 对动画的要求、对新版设计画布的意见，以及两个决定

说明：第二部分第 9 条里的“选中的缩略图永远在顶栏中心位置”，正文理解为“底栏的正中间”，因为缩略条在底栏（第 6.7 节）。

> 接下来的建议都针对动画，其中一部分可能比较疯狂：
>
> 1. 如果报告里有提到卡片动画，那些都是我的亲手设计，我喜欢看到相同的卡片在不同布局切换时表现为移动而非消失后再出现，看起来很优雅，卡片在缩放和变形时，封面、标签、标题作者等文字都应该完美缩放与平移，文字类我甚至希望能逐字移动而非先消失在出现的“切换式移动”，这里指的是缩放以及字间距变化的情况
> 2. 迁移至 WasmJS 后，我还要把作品打开动画重新加回来，鉴于当前的设计已经不适合全部做成缩略图放大变成原图（因为有些作品封面不进入可观看媒体），我想设计一个全新的打开方式，这里我会让鼠标悬浮在作品上时，作品封面下沉一圈，背后像很多张相片散落一样冒出这个作品的其他图片，至于能看到前几张你来定，我估计三四张差不多，如果这个作品就一张图那就不给这个效果；打开动画改成整个作品卡片放大成灯箱，如果缩略图本身等于第一张媒体，那就直接让封面动态缩放+动态裁切，如果和前面提到的一样封面不属于作品内容，那就让背后的真正第一张媒体滑出来然后动态缩放+动态裁切，封面、其他卡片、作品标题、作者、标签等其他元素就地淡出；当我们在灯箱内跨作品切换时，背景应自动把切出去的作品重新淡入，并把切到的作品就地淡出，确保视觉上连贯无瑕疵
> 3. 我们的全局动画都应该像 iOS 一样优雅，各种动画都需要可中途打断（优雅倒放动画路径，但动画曲线不应该硬生生倒放，而是维持原动画曲线（应该是，这样看起来回去的动画不会很奇怪）+ 反转后的路径回到原位）、动画曲线也应优雅且统一
>
> 接下来的建议都针对你刚刚交给我的新版 Canvas：
>
> 1. 侧边栏三横线应该换成灯箱里那种侧边栏图标，并且放在侧边栏标题区域的右侧，侧边栏收起时这个按钮在收起过程淡出，随后可以在鼠标悬浮到画廊图标上时淡入淡出切换出来
> 2. 侧边栏展开收起的动画别忘了
> 3. 让你用分割线，没让你把平台和文件夹这俩标题删了，另外下半截文件夹属于直连文件系统而不经过数据库的，命名为“全部文件”
> 4. 标签的背景怎么删了，把圆角矩形加回来
> 5. 用于长文本的淡化记得不要漏掉任何淡入淡出行为，我不想看到任何无过渡硬切换
