# 原生控制与原创许可

## 状态

已接受

## 背景

2026-10-21 用户经 67 号指令授权修复原生四页管理控制与生命周期，保持身份核验，建立独立 race 环境，并采用与独立 Gallery 相同的 AGPL-3.0。剩余 Node 替代及生产 Runtime 迁移不属于本轮。

## 决策

- 原生 IPC 仍只接受本窗口的顶层 frame、精确的管理文档路径与操作白名单；页内 hash 是四页路由，不是另一个可信文档。其他文件、查询串和网络地址不获准。
- 进程身份继续由 PID、创建时刻、可执行路径共同决定。Windows 查询改用 System.Diagnostics.Process 的本机进程句柄，避免每次经过 WMI/CIM 服务；创建时刻保留原记录的微秒精度。每次重新查询，不增加身份缓存、失败重试或 PID-only 回退；无法核验仍拒绝操作。
- 状态读取失败清除旧服务状态；本机宿主无法读取控制状态时不伪报已停止。页面、服务行与侧边栏使用同一状态。
- 原生窗口采用基线默认与最小尺寸。自动验证等待真实就绪，而不是短暂按钮状态；失败清理先结束本测试所有的 Runtime，再等待 Playwright 的 Windows 启动壳退出，日常退出管理器仍保留服务。
- race 编译器仅由忽略的本机路径文件或命令环境指定；环境只传给当前子命令，不修改系统或其他工具安装。
- LICENSE 与独立 Gallery 全文字节一致。README 采用相同许可表述；需要许可标识的 npm 字段写 SEE LICENSE IN LICENSE。仅 v3 或 v3 及以后尚待用户决定；第三方材料不改许可，字体不入库。

## 后果

认证强度、实例归属、Go 扫描与 WAL/FULL 没有因界面问题放松。此检查点不代表部署，也不是完整 Go 后端。可见细节的待确认项另见 [adr-4](adr-4-manager_details.md)。
