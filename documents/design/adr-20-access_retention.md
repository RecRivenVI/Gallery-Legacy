# 访问和封禁记录保留

## 状态

已接受

## 背景

访问历史原先按时间和数量裁剪，与程序日志共用有限保留的思路。生产迁移后，用户决定访问和封禁记录长期保留，运行日志继续轮转。

## 决策

审计数据在实例的独立 SQLite 内按批提交。首次打开时读入已有 JSON 快照，原件保留作为升级恢复材料。客户端和每日统计持续保留，请求与封禁动作分别查询。临时封禁到期解除，其记录仍可查询。手动清空只清理访问统计与请求事件。

## 后果

审计数据库随活动增长，管理器对查询进行分页。可恢复的记录来自本机现存快照和已保留的旧版审计。运行日志策略见[管理器指南](../usage/guide-manager.md)。
