# 扫描流水线

全量和增量共用 Go 标准库遍历、准备、平台暂存与唯一 writer。HTTP／媒体读取仍由 Node 提供，不启动第二个数据库 writer。

```text
平台根 → 根／作者成员 → 有界作品观察与签名
  → metadata 只读句柄与解析 → 每平台 spool
  → 完整平台 FIFO → 完整作品短事务
  → Catalog + Search + 计数 + revision + 已处理签名
```

- 全量重新提取选定范围，不先清空库；增量只复用已提交、版本匹配且属性签名合格的作品。每次仍枚举所选后代，不使用目录 mtime 单独跳过。
- 根／作者成员按批暂存，不再重复保存作品的整份媒体清单。暂存可重建，不作为下次复用证明。
- 作者协调和大作者作品窗口有界；全局许可与物理盘许可联合授予，等慢盘不占全局槽。默认值与上限以 Go 配置代码为准。
- 完整平台可提交申请，不等所有平台结束；一个 writer 依次处理平台，内部仍是短作品批次而非整平台巨型事务。
- 正式 Catalog 保持 WAL/FULL；临时清单的弱持久化不影响已提交事实。自动与周期 PASSIVE checkpoint 不是 WAL 硬上限。
- metadata 前后大小／时间／句柄核验、目录身份／最终路径／reparse 检查保留；错误传播到完整性，不能把权限或竞态当不存在。
- 删除仅在范围完整且原生确认路径消失后执行。取消／失败保留已提交事务，未知版本或不合格签名不能认证复用。
- 作者资料按所有作品的确定顺序选权威锚点，不按并行到达顺序覆盖。必要时只重读未变锚点，不重写该作品。

当前检测模型不保证识别保留 size／mtime 的内容替换；没有跨平台 watcher。大作品限制及未完成事项见[技术债](../project/debt-runtime.md)。
