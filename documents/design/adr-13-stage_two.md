# 数据与个人阅读能力

## 状态

已接受。依据用户 2026-11-03 第二阶段任务及用户授权外部评审决定的界面设计。

## 背景

元数据字段与显示存在遗漏，缩略图只有单档并依赖每图外部进程，动态 JSON 读取难以发现契约不一致。用户新增多字段搜索、账号个人数据、作者关联与漫画阅读。

## 决策

1. 第一阶段完成后连续实施两部分，不等待人工验收。只用 SSD 合成数据；保留第一阶段压缩包和最终空实例，不读取真实作品，不在 G: 测试。
2. 固定每平台字段表与命名解析函数，补作品类型、系列、分级、计划、关系与指标；只对 pixiv 按 x_restrict 显示全年龄/R-18/R-18G。Pawchive 原平台 ID 只用于展示。
3. 精确键自动关联 Fanbox/pixiv、Patreon/X；链接线索只是候选，需要用户确认。作者资料接作者页；作品社交关系接详情。远端访问权限不能决定本地文件可读性，停止写 work_access；界面使用解析结果，停止重复写 structured_sources 原文。媒体声明保留给匹配正确性与图库检查。既有公共格式的表保留，升级重解析时清掉停写表的行。
4. 本地账号及收藏、评分、个人标签、历史、继续阅读取代旧“不做账号”和“不新增浏览记忆”的范围限制。没有社交、邮箱、权限分级或多租户；个人数据存实例，游客仍可浏览。冻结设计与旧 ADR 正文不改。
5. 搜索默认仅查可见卡片字段；新增前缀、包含/排除、高级面板、条件跨平台查询。先在约 39 万合成作品上定目标；不提供无条件跨平台总览。
6. 新界面按本次附件：筛选即时生效、面板会话合并历史；删除账号/收藏夹和清空历史只在原位确认。作者关联对所有用户有效；阅读支持单页、双页、连续、RTL 与系列。
7. 公共接口由 api 生成强类型数据类；检索统一一份结构。已有实例升级使用既有目录记录，仅重新解析 metadata，不重新枚举媒体树。
8. 缩略图改为 libvips 进程内分档、ThumbHash 与独立 SQLite 索引；视频继续 FFmpeg。S 常驻，M/L 按 20GB 默认容量淘汰；封面后台生成与扫描错开，可暂停恢复。具体尺度和实现调整依据合成实测补在本 ADR。
9. 版本选择主版本升级，唯一数值在 Cargo.toml。保留公共 Catalog 格式与既有恢复基线；live 升级到 5，增补可随恢复快照保留的 work_details/author_keys 表，旧库在维护所有权内按已记录作品路径重读 metadata，逐作品完整提交且可续。媒体与媒体声明不重新枚举，物理 ID/数量不改变。
10. Windows 直接调用官方 libvips DLL 的 C ABI，HTTP 与 UI 不提权，也不加入 CGO 产品依赖。官方 web 包覆盖已声明图片格式，S/M/L 几何以附件为准；S 输出复用于 ThumbHash，避免 shrink-on-load JPEG 被重复消费导致顺序读取错误。DLL、依赖清单和许可原文随包提供。

11. 静态与 live 使用 api/search.sql 的同一模板，仅区分库位置和表前缀，FTS 与短词读取合并。旧静态基线没有 has_readable 投影时用只读连接的临时投影计算可看内容，不改不可变恢复文件。旧静态没有补充表时字段为空，恢复到工作库后按 metadata 路径升级。
12. 占位使用 ThumbHash DC 均色与原始宽高；卡片按显示尺寸和 DPR 选 S/M，看图先 S 再 L，超出 L 分辨率才读原图；动图和视频保留浏览器播放。S 常驻且命中不更新 last_used，M/L 的 20GB 默认按二进制容量计。后台封面目前在任一扫描期间暂停，作为避免同盘竞争的保守实现，可在后续实测后细化到单盘。
13. 配置类型直接从 runtime-config.schema.json 生成；其他记录、分页、状态、偏好、字体清单从 public.json 生成。页面不按字符串取字段，动态 JSON 只在多态传输、路由与序列化边界。后台状态不加入稳定管理页壳的比较值。

14. 第二部分先用 390,000 作品查询语料记录旧查询：中文短词约 7 秒，普通翻页几十毫秒。目标：同语料含精确计数和 48 张卡片的宽匹配 p95 不超过 1 秒，精确 ID/标签/作者和稀有词不超过 250 毫秒；分别记录语法组合与跨平台。它是查询目标，不代表 HTTP、缩略图或浏览器延迟。短词索引语料使用安全超集并由精确文本核验，属于保守候选规模；无来源文件或真实内容。
15. 账号使用实例 state/people/personal.sqlite，独立 WAL/FULL 写连接；目录读取连接只读附加个人库，账号 ID 限定每次请求。个人作品以平台与规范相对路径关联，不以可重建的目录 ID 关联。可选密码使用随机盐与标准库 PBKDF2，不做邮箱、角色、远端账户或额外安全流程。

16. 标签筛选数组使用 JSON 网址参数，避免把标签自身的逗号拆开。多词仍可分别命中标题、作者名或标签，不强迫所有词出现在同一字段。精确 ID 查询把平台范围下推到既有复合索引；多普通词在紧凑可见字段投影上一次核验，避免重复建立大候选集。没有新建数据库或放宽正确性检查。
17. 个人数据以平台与规范相对路径为键，不猜测重复来源 ID 的归属；目录改名后的个人记录不自动转移到新路径。忽略的作者对即使存在其他关联路径也不重新出现；已知官方资料链接只是候选，精确对应键才自动关联。
18. 漫画默认依据已知页宽高判断长条多数，不为推断默认方式预读整本原图。宽高不足时沿用设备上的漫画默认方式，用户可选连续阅读。动画或视频混合的作品保留单页播放，不把动图冻结成漫画页；这是本轮保守处理，待试用后决定是否增加专门混合阅读布局。
19. 作者头像仍尊重用户先前的默认隐藏开关，显示时使用占位。账号头像可从与背景共用的分页图片选择器选取；图片失效时退回名称首字。账号列表当前项在前，其余按最近创建在前，便于切换。账号偏好同步到独立个人库，浏览器保存最后一次启动主题，访客另存一份偏好，退出后恢复。
20. 新阅读菜单与补全继续使用同一个 Compose 场景，复用现有面板；不使用会丢失主语义 owner 的原生 Popup。外层弹层在上层面板出现时暂停焦点退出限制，关闭后恢复，保留 Escape 和输入框可用性。
21. counts.media、页数筛选、继续阅读及进度使用可阅读页数；物理文件计数不变。封面、点文件和提取预览不算没看完的页。个人动作遇到扫描刚移除的作品返回 WORK_NOT_FOUND，不索引空结果。

## 后果

产品版本按数据与功能改动幅度升级。账号密码、读取节流、缓存迁移与新增查询需要专项验证；截图不能替代真实 IME、真机、原生宿主与首次扫描。上述人工验收统一延后，不把未验收写成通过。
