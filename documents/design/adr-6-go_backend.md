# 剩余后端迁移到 Go

## 状态

已接受。

## 背景

用户在 2026-10-22 的 72 号任务中要求，将 HTTP、读取、媒体、schema／静态恢复及任务生命周期迁到 Go。Electron、CanvasKit 与四页管理端不换技术栈；生产实例和历史 Runtime 不动。

## 决策

先冻结[行为合同](../reference/protocol-backend.md)，用独立冻结 Node 构建产生合成黄金结果。协议和存储定义集中于 api；Go 用嵌入的同一来源，Node 过渡期也从该处读取，不复制版本和 DDL。

按[迁移计划](../project/plan-go_backend.md)分批实施和提交。Go Reader 的一个响应使用一个只读事务；恢复只接受完整验证的 READY，工作库升级保留事实、高水位和身份。新库在 FULL 事务完成并关闭后以不覆盖目标的持久化移动安装；原有数据库不因初始化失败被空库取代。

保留 Node 冻结对照于仓库外，直到替代差分完成。默认入口切换前，不把独立实现或黄金测试称作完整 Go 服务。切换后只有 Go writer；Electron 仍负责窗口、托盘、系统对话框和固定白名单桥。

## 后果

Node 后端只在对应替代已经验证后退出构建；不能为删除旧实现而删除既有行为测试。版本、字符编码、游标字节、路径、错误码、Range、生命周期与进程身份均需对照，不用测试数量代替用户试用。
